# Motorola dubai boot chain

## Verified state

- ABL fastboot (`is-userspace: no`), product `dubai`, XT2203-1, unlocked bootloader, active slot `_b`.
- Slot `_a` is marked `slot-unbootable=yes`; it is not a fallback. The backup of the original images is verified with two SHA-256 reads.
- CSOT NT37701 panel confirmed by the Android cmdline and fastboot `primary-display`.
- `fastboot boot` works with the official LineageOS boot image, but temporary mainline v2 images return to fastboot.
- Flashing mainline `boot_b` alone, without changing DTBO, fails; rollback to LineageOS was verified.
- **Flash of mainline `boot_b` plus an empty `dtbo_b`: boot succeeded.** Kernel 7.2.9-dubai+, initramfs, ACM/NCM/SSH, and read-only storage were verified.

## Layout verified via fastboot

- `boot_a`/`boot_b` and `vendor_boot_a`/`vendor_boot_b`: 96 MiB each.
- `dtbo_a`/`dtbo_b`: 24 MiB each; `vbmeta_a`/`vbmeta_b`: 64 KiB each.
- `super`: 0x214000000, with dynamic logical partitions; it is not a Linux rootfs to overwrite.
- `userdata`: 0x1b166fb000, physical and shared between the slots; unused by the NBD strategy.

## Mainline image requirements

- Boot header v2, page 4096, offsets and appended DTB taken from pmaports.
- Cmdline `earlycon console=ttyMSM0,115200n8 console=tty0 panic=10`; ABL overwrites or appends its own arguments.
- Empty 24 MiB DTBO, exactly as generated by the pmaports device package. The Android DTBO is not compatible with the mainline path.
- No vbmeta change was required in the successful tests; do not disable further checks.
- `reboot-to bootloader` and `reboot-to fastboot` from the initramfs are ignored and return to the normal `_b` boot: for later flashes use Power+Volume Down.

## Current artifacts

- LLVM kernel/modules: `out/kernel-llvm`.
- Diagnostic initramfs with modules/SSH: `out/initramfs-llvm-ssh`.
- Initramfs with GPU firmware and the NBD client: `out/initramfs-nbd`.
- Arch/NBD boot image: `out/images-nbd/boot-dubai-csot-UNTESTED.img`.
- Empty DTBO: `out/images-llvm/dtbo-empty.img`.

The boot image stays labeled UNTESTED in the filename even after M3, because every new userspace variant needs a separate check. The NBD rootfs is exported from the PC as a qemu-nbd snapshot; no installation on `userdata` is required for M4.

## Recovery

Rollback of boot_b/dtbo_b uses only the verified original copies in the private directory. Do not change the slot and do not restore partitions that were not modified. The full runbook is in `docs/RECOVERY-RUNBOOK.md`.
